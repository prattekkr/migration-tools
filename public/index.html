            XMOD S7 Package Updater
            ZIP → ZIP rewrite
          

          

            

              Post-processes a downloaded content-package ZIP: swaps DAM paths back to original asset URLs
              (via asset-mapping.json) and/or relocates the JCR content to a new target path —
              auto-detecting the source path from META-INF/vault/filter.xml.
            

            

              

                
Steps

                
    
                  
  1. Upload: Select a bundle ZIP (with asset-mapping.json + inner content zip) or a plain content ZIP. Optionally attach an asset-mapping.json for a plain ZIP.
    2. 
                  
  2. Inspect: See whether it's a bundle, the detected source path, and how many asset replacements will run.
    3. 
                  
  3. Target (optional): Enter a target JCR path to move the content; leave blank to only replace asset references.
    4. 
                  
  4. Process: Download the updated ZIP. The change log lists every modified, sanitized, and created entry.
    5. 
                

              

              

                
Notes

                
    
                  
  • Asset replacement maps damPath → url (the inverse of the Image/Asset tool) and runs for bundles or an attached mapping.
    • 
                  
  • Path move renames jcr_root{source} → jcr_root{target}, rewrites path strings in files (incl. filter.xml), and creates intermediate cq:Page nodes.
    • 
                  
  • Binary assets are copied untouched; bare & in XML is escaped to &amp;.
    • 
                  
  • This tool intentionally edits package metadata when moving — that's required for the new filter roots.
    • 
                

              

            

          

        

      


      
      

        

          

            
            Page Metadata Migration
            AEM → EDS
          

          

            

              Reads page properties from AEM author and writes the mapped values into Edge Delivery Services (EDS)
              metadata sheets. Useful for bulk-migrating titles, descriptions, tags, and any custom properties
              without touching each page manually.
            


            

              

                
Steps

                
    
                  
  1. Step 1 — Configure: Enter your AEM Author URL + credentials and the target EDS SharePoint / Drive URL. Click Save Config, then Test Connections to verify both are reachable.
    2. 
                  
  2. Step 2 — Discover & Map: Enter one or more AEM root paths (e.g. /content/abbvie-com) and click Discover Pages. The tool streams all pages via AEM QueryBuilder. Once done, map each AEM property to its EDS column name. Optionally apply a transform (uppercase, lowercase, date format, etc.).
    3. 
                  
  3. Step 3 — Bulk Update: Review the discovered pages, check / uncheck individual pages, then click Start Bulk Update. Progress is streamed live. Download the CSV or log when finished.
    4. 
                

              

              

                
Tips & Notes

                
    
                  
  • Credentials are saved to config.json on the server — no need to re-enter each session.
    • 
                  
  • Property mappings are saved to mapping.json and persist across sessions.
    • 
                  
  • Use Preview Update on a single page before running the full bulk update.
    • 
                  
  • AEM SSL errors are suppressed automatically (rejectUnauthorized: false).
    • 
                  
  • The EDS URL must point to the metadata sheet of your SharePoint workbook.
    • 
                

              

            

          

        

      


      
      

        

          

            
            Image / Asset Migration
            DAM → Dynamic Media
          

          

            

              Rewrites AEM DAM asset URLs inside an EDS HTML/JSON ZIP package to Dynamic Media Open API (DM) URLs.
              Supports multi-environment configs (dev / stage / prod) and custom path mappings.
            


            

              

                
Steps

                
    
                  
  1. Step 1 — Environment: Pick a mode (AEM to DM or Domain Swap) and select the target environment. Use Use AEM from Page Metadata Config to auto-fill AEM credentials.
    2. 
                  
  2. Step 2 — Asset CSV: Click Build CSV to query AEM DAM and generate a mapping of old DAM paths → new DM URLs. The status pill shows whether a CSV already exists for the environment.
    3. 
                  
  3. Step 3 — Upload ZIP: Upload your EDS output ZIP. Add root path mappings if your DAM paths differ between environments. Click Process ZIP to rewrite all asset references.
    4. 
                  
  4. Step 4 — Download: Download the patched ZIP and a change report CSV. For Domain Swap mode, upload the ZIP and enter old / new domain strings.
    5. 
                

              

              

                
Tips & Notes

                
    
                  
  • Environment configs live in site.config.json. Edit it to add new environments or change DM delivery domains.
    • 
                  
  • The asset CSV is cached per environment in data/. Rebuild it only when DAM assets change.
    • 
                  
  • Root mappings let you strip or replace a DAM path prefix before looking up the DM URL (useful when dev/stage paths differ from prod).
    • 
                  
  • Custom mappings let you hard-code specific DAM path → DM URL pairs that override the CSV.
    • 
                  
  • Build logs stream in real time. Scroll the log box to see per-file results.
    • 
                

              

            

          

        

      


      
      

        

          

            
            Link Checker
            AEM Package → Link Audit
          

          

            

              Scans the EDS / Franklin pages inside an AEM content-package ZIP (only XML carrying
              cq:template="/libs/core/franklin/templates/page") and flags five common
              migration mistakes, then fixes them.
            


            

              

                
Steps

                
    
                  
  1. Upload ZIP: Select an AEM package ZIP (nested or flat).
    2. 
                  
  2. Site root: Enter the package's full site root (e.g. /content/abbvie-nextgen-eds/corporate/abbvie-com/ch/fr), or click Detect. Every internal page link is validated against it.
    3. 
                  
  3. Environment: Pick the target environment — used for PDF / DAM / Scene7 → DM Open API lookups (from the asset-map built in the Image / Asset tool).
    4. 
                  
  4. Scan: A pass/fail card appears for each of the five checks, with counts and example links.
    5. 
                  
  5. Absolute domains: Tick the domains that are truly external (left as-is); the rest are treated as internal and re-rooted.
    6. 
                  
  6. Fix: Click Fix all, or fix one category with its own Fix button. Downloads the patched ZIP + a change-report CSV.
    7. 
                

              

              

                
The five checks

                

                  
Short paths Relative page links not rooted at the site root → re-rooted to it

                  
Absolute URLs Internal pages written as full http(s) URLs → domain stripped, re-rooted

                  
PDFs not on DM PDFs still on /content/dam → DM /original/as/ URL

                  
DAM assets not on DM Images / assets on /content/dam → DM Open API URL

                  
Absolute Scene7 *.scene7.com/is/image → DM Open API URL

                

                

                  
Notes

                  
    
                    
  • Only Franklin pages are checked. META-INF, filter.xml, redirects/config nodes and XML namespaces are excluded.
    • 
                    
  • Content fragments and full cross-locale /content/ links are recognised and left untouched (cross-locale links are listed for review).
    • 
                    
  • Per-category fixes stack: fix one type, re-scan, fix another. Nothing changes unless it matches.
    • 
                  

                

              

            

          

        

      


      
      

        

          

            
            Package Creator
            Package Manager API
          

          

            

              Bulk-creates an AEM content package and applies a set of workspace filter roots via the
              Package Manager API — then optionally builds it. Useful for assembling an export package
              over many content paths without hand-editing filter.xml.
            

            

              

                
Steps

                
    
                  
  1. Connection: Enter the AEM author host, username and password and click Test Connection. Use Use AEM from Image/Asset config to pre-fill the host.
    2. 
                  
  2. Package Details: Set the package name, group, version and optional description.
    3. 
                  
  3. Filter Paths: Pick the default filter mode, then paste content paths (one per line) or upload a .txt file. Each path becomes a filter root.
    4. 
                  
  4. Create: Click Create & Add Filters, or Create, Add Filters & Build to also build. Progress streams live; a link to the package opens it in Package Manager.
    5. 
                

              

              

                
Notes

                
    
                  
  • Filter modes: replace (replaces existing content), merge (adds new, keeps existing), update (only updates existing nodes).
    • 
                  
  • Only lines starting with / are treated as paths; everything else is ignored.
    • 
                  
  • Self-signed AEM SSL certificates are accepted automatically.
    • 
                  
  • The package is created under /etc/packages/{group} using the name and group you provide.
    • 
                

              

            

          

        

      


      
      

        

          

            
            Property Updater
            JCR Bulk Edit
          

          

            

              Discovers JCR nodes under a root path in AEM and bulk-sets a single property value across
              hundreds of pages or assets in one pass — without needing to open each page in the AEM UI.
            

            

              

                
Steps

                
    
                  
  1. Content Type: Choose Pages (jcr:content) or Assets (jcr:content/metadata) — determines which node is read and written.
    2. 
                  
  2. Environment & Root Path: Select an environment and enter the JCR root path (e.g. /content/abbvie-com/us). Optionally set a node pattern to filter by node name.
    3. 
                  
  3. Discover: Click Discover to stream all matching nodes. A table shows each path with its current property value and whether the value is missing.
    4. 
                  
  4. Select & Filter: Use Select All, Deselect All, or Select Missing Only to choose which nodes to update. Filter by path using the search box.
    5. 
                  
  5. Set Property: Enter the property name, value, and type (String, Boolean, Long, Date). Click Run Update.
    6. 
                  
  6. Export: Download a CSV log of every updated node and its result.
    7. 
                

              

              

                
Notes

                
    
                  
  • Discovery uses the AEM QueryBuilder API and streams results via SSE — large trees stream progressively.
    • 
                  
  • Select Missing Only selects nodes where the property does not yet exist — ideal for backfilling a new property.
    • 
                  
  • Updates run with configurable concurrency (default 5 parallel requests) to avoid overloading AEM.
    • 
                  
  • The node pattern field supports simple glob-style matching against the node name.
    • 
                  
  • All write operations use the Sling POST servlet (application/x-www-form-urlencoded).
    • 
                

              

            

          

        

      


      
      

        

          

            
            Lighthouse Auditor
            Performance · SEO · A11y
          

          

            

              Runs Google Lighthouse audits against a list of URLs in parallel and presents a searchable,
              filterable score dashboard — useful for bulk-auditing EDS pages before or after go-live.
            

            

              

                
Steps

                
    
                  
  1. URLs: Paste one URL per line in the text area (supports 1000+ URLs).
    2. 
                  
  2. Device: Choose Desktop or Mobile emulation.
    3. 
                  
  3. Concurrency: Set how many audits run in parallel (default 3; increase for faster runs on powerful machines).
    4. 
                  
  4. Run Audit: Click Run Audit. Progress updates live. Each completed page shows scores for Performance, Accessibility, Best Practices, and SEO.
    5. 
                  
  5. Review: Use the score-slab filters (>90 / 80–90 / 60–79 / <60) and the search bar to find underperforming pages. Click any row to see the full Lighthouse report.
    6. 
                  
  6. Export: Download a CSV of all scores for further analysis.
    7. 
                

              

              

                
Notes

                
    
                  
  • Each audit runs in a separate child process to avoid Lighthouse's internal performance-mark conflicts when running multiple audits.
    • 
                  
  • Mobile scores differ from desktop by design — Lighthouse simulates a throttled 4G connection and a mid-tier device for mobile.
    • 
                  
  • Score slabs: 90–100 Good   80–89 Needs improvement   0–79 Poor.
    • 
                  
  • Auditing requires Chrome to be installed on the server machine.
    • 
                  
  • Results are kept in memory for the current session — re-running clears previous results.
    • 
                

              

            

          

        

      


      
      

        

          

            
            EDS Site Creator
            EDS Repoless Provisioning
          

          

            

              Bulk-creates EDS repoless country/language sites across environments — registering each site in
              the Admin API, creating its query index YAML, and optionally setting up the AEM cloud configuration
              node and applying cq:conf to the content root.
            

            

              

                
Steps

                
    
                  
  1. Sign in: Click Sign in to admin.hlx.page. A Chrome window opens — complete Adobe SSO. The auth_token cookie is captured and cached for 6 hours.
    2. 
                  
  2. AEM Credentials: Enter the AEM author service account username and password for the selected environment. Click Save credentials then Test connection to verify.
    3. 
                  
  3. Select Environment: Choose Dev, Test, Stage, or Prod from the dropdown. The author host and branch are shown for confirmation.
    4. 
                  
  4. Select Sites: Check the country/language rows you want to create. Use Select all, Select ready, or filter by country/language/path. Click { } to preview or edit the JSON / YAML / AEM config payloads before sending.
    5. 
                  
  5. Create: Click Create selected. The pipeline columns show live status: S Site config · Q Query index · C AEM cloud config · R Apply cq:conf to root.
    6. 
                

              

              

                
Notes

                
    
                  
  • The auth token and AEM credentials are encrypted with AES-256-GCM and persisted in site-creator/.auth-cache.json — they survive server restarts.
    • 
                  
  • Payloads are driven by site-creator/environments.json, sites.json, site-defaults.json, and aem-config-defaults.json. Edit these files to add environments or sites.
    • 
                  
  • The { } button lets you inspect and override the JSON/YAML for a specific site before running — overrides apply only to the current session.
    • 
                  
  • AEM config mode: Create (full subtree) imports the full conf node tree; Update config only patches only jcr:content on an existing node.
    • 
                  
  • Sites that already exist in admin.hlx.page are skipped gracefully (HTTP 409 treated as success).
    •
